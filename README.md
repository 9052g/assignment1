# Why designers should learn programming

In an era where AI tools can generate functional code with simple prompts, many designers begin to question whether learning programming is still necessary. If artificial intelligence can write code automatically, why should designers spend time studying syntax and logic? My argument is straightforward: AI is a powerful tool to produce code, yet only designers with programming literacy can judge, adjust, and truly own their digital creations. Programming is not about transforming designers into professional software engineers. Instead, it gives us greater control over digital media, helping us turn creative ideas into tangible, custom-made works. My experience of making the Schotter generative art is a good example. Even though AI can generate similar grid graphics, I need basic coding knowledge to tweak parameters such as SEED and CHAOS to get the visual effect I want.

This gets to the core gap between describing a creative outcome and specifying it precisely. Anyone can prompt an AI to generate “a chaotic grid pattern that feels unsettling”, but getting exactly the visual rhythm, density, and degree of distortion you envision requires more than vague description. It requires the ability to define rules: how much each rectangle shifts, what randomness range to use, how lines align across the grid. This is not just technical skill—it is a form of precise creative communication. When you write code, you are not giving a suggestion to a machine; you are translating your visual intention into unambiguous, executable rules. AI can interpret loose prompts, but it cannot know the specific aesthetic judgement you hold in your head. Programming literacy closes that gap.

This tension between machine creation and human authorship is not new. Back in the 1960s, early computer artists Georg Nees and Frieder Nake faced criticism that machines would replace artists. At that time, critics believed automated graphics removed human creativity, just like many people argue AI will replace designers today. Their works demonstrated that the computer is not an artist by itself. Instead, it acts as a medium that artists steer through rules and logic. Reas and McWilliams (2010) argue in *Form+Code* that code is a fundamental material for contemporary design. Many people misunderstand programming as purely technical work reserved for software engineers. However, for designers, code is a way to define visual rules and build generative systems. With coding literacy, designers can create variable graphics, interactive installations and dynamic visual outputs that would be impossible to draw manually.

Even if you never build a full project from scratch, programming literacy gives you the critical ability to read and evaluate code that AI generates. A machine can output syntactically correct code that runs, but it cannot tell you whether it solves the right design problem. It can generate a working interactive prototype, but it cannot judge if the interaction feels right, if the motion timing matches your concept, or if there are unnecessary limitations built into the system. Without the ability to follow the logic behind the output, you are entirely dependent on the AI’s defaults and assumptions. You cannot reliably tell good output from bad, or spot where the machine missed your creative intent. This is the difference between using a tool and being directed by it.

This is a principle common to all creative disciplines. Painters learn the properties of paint not to become chemists, but because understanding their material expands what they can express. Photographers study light and optics not to be engineers, but because knowing how their medium works lets them see more possibilities. For designers working with digital systems, code is the fundamental material. Not understanding it does not just make you slower—it narrows the scope of what you can even think to make. You only work within the boundaries of what your tools present to you, and if you do not know how those tools work, you never see beyond their default options.

Learning programming also helps designers prototype interactive concepts quickly. Instead of waiting for developers to build a demo, designers can test their own creative ideas in code and iterate rapidly. Traditional design tools constrain creators to static outputs that can only be modified manually. Coding breaks this limitation by letting designers define rules instead of drawing every single element. This shift in thinking is one of the core ideas from *Form+Code*: design can exist as a set of instructions, not only finished images (Reas & McWilliams, 2010). Learning programming teaches designers to think systematically. They learn to break complex visual problems down into small logical steps, a skill useful for all design work, not only generative art. Even if a designer does not become a full-time coder, this computational thinking changes how they approach sketches, prototypes and creative problem-solving.
